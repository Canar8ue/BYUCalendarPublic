# Project bug audit — November 10, 2026

Status: published November 10, 2026 (America/Denver), code commit `2d13eca`, deployed from a clean worktree. No migration, manual production data change, environment change, or external message. Existing marketing/font work was left intact.

## Scope

Reviewed calendar state, filters and search, date/time handling, source normalization, exports and subscription tokens, account requests, preference/RSVP persistence, responsive layouts, map integration, and game input/lifecycle behavior. Exercised the existing full domain suite and production-Worker integration suite. Browser work used the built application, a separate local D1 database, intercepted verification emails, and a mock search provider. GLM delegation tools were not available in this session.

This is a broad regression audit, not a claim that every line or every physical device has been tested.

## Changes

| Area | Reproduced problem or verified code defect | Result |
| --- | --- | --- |
| Build | The About page contained committed merge markers. | The page compiles again. |
| Shared links | `view=week` was omitted from URL restoration; unknown filters could make the calendar inexplicably empty. | All four views restore; URL filters are deduplicated and restricted to supported values, including RSVP / tickets. |
| Responsive state | Crossing the phone breakpoint silently reset Week/Month to Day. | Resizing preserves the selected view. |
| Calendar dates | The current month/week anchor used the visitor/server's day; “this month” calculated its end in the host timezone. | Campus dates determine both, including UTC month/year boundaries and leap days. |
| Week grid | Week used Monday-first columns despite the documented Sunday-first calendar; dotted separators compared full minutes. | Week and Month use Sunday-first grids; hour separators compare hours. |
| Unknown times | After-hour searches treated TBA placeholders as real hours; the 17:19 UTC sentinel became 10:19 AM after DST. | TBA records fail time-of-day predicates and remain labeled TBA through winter. |
| Source duration | A retained football listing ran from October 31 to November 14 and polluted every intervening day. | Individual named team contests with ends over 24 hours have the suspect end withheld and explained. General timed records retain the existing 31-day guard; all-day ranges and multiday tournament formats remain supported. |
| ICS timezone | Floating starts inherited `X-WR-TIMEZONE`, but their ends defaulted to Mountain Time. | Both endpoints inherit the same calendar timezone. |
| Directions | Off-campus names such as “Rome, GA” and “Boulder, Colorado” gained “Provo, UT.” | Published city/address text is retained; resolved campus buildings keep their canonical Provo destination. |
| Search requests | Aborting one interpretation could prevent the next query from starting; old requests could clear a newer loading state. | Requests are independently cancelled; loading feedback belongs to its query. |
| Search fallback | Relaxing unmatched keywords also removed the requested dates/hours and unioned model categories with explicit filters. | Keyword fallback keeps date/time restrictions; explicit category filters retain precedence. |
| Search validation/cache | Impossible dates normalized to another day, distant end dates bypassed bounds, midnight-only searches were rejected, and relative dates could remain cached after midnight. | Real date round trips and bounds are enforced, midnight is valid, and cache keys include the Mountain calendar day. |
| Autocomplete | “IS / AIS” and its networking suggestion inserted lowercase `is`, which the parser treats as ordinary prose. | Completion inserts uppercase `IS`; suggestion matching remains case-insensitive. |
| Saved calendars | Overlapping writes were assembled from the same old preference snapshot. | A queue applies each change to the last acknowledged state, preserving consecutive saves/filter edits and recovering after a failed write. |
| Preference persistence | Preferences committed before RSVP mirroring; failure or concurrent writes could leave the tables inconsistent. | The preference payload, removals, and batched inserts commit atomically. Saved IDs are deduplicated; the response includes the canonical stored preferences. |
| Initial preferences | Saving before preferences finished loading could replace an existing calendar with an empty initial snapshot. | Saves are blocked until preferences have initialized successfully. |
| RSVP display | Saving/removing did not refresh the open event's list; another event's faces could linger while loading. | The list refreshes on membership changes and clears stale entries. |
| Account copy | Signup said names/emails were never shown, contradicting member-visible RSVP lists; failed sign-in claimed no account existed. | Copy explains RSVP visibility and gives an honest sign-in/create/reset choice without disclosing account existence. |
| Feed tokens | A valid token with extra dot-separated suffixes was accepted. | Verification requires exactly two segments. |
| Narrow headers | Sign-up overflowed at 651px and on 320px phones; saved-count badges could consume the remaining phone space. | The brand/navigation compact at those widths, narrow count badges hide, and home links retain accessible names. |
| Account layout | The longest staff-area option forced a 379px select inside a 320px screen. | The select can shrink within its account card. |
| Listing forms | Switching between timed and all-day fields remounted inputs with incompatible or empty values, losing entered dates. | New/edit forms preserve dates, respect midnight-exclusive ends, and restore the original hours when toggled back without edits. |
| Filter-name validation | Empty names invoked native browser validation over a blurred dialog; whitespace-only names silently did nothing. An iOS background glitch was reported for this interaction. | Both filter forms show an accessible inline name error, bypass the native validation popup, and use an unblurred dim backdrop. Named saves still follow the same persistence path. The exact reported iOS rendering was not independently reproduced. |
| Filters/dialogs | Tall filter menus exceeded the screen; long words could overflow; dialog border/padding clicks could act as backdrop clicks. | Menus scroll within available height, long text wraps, and dismissal checks the dialog's actual bounds. Single-event map/day counts use correct singular text. |
| Network recovery | Event/account/preference reads could hang indefinitely; timeout failures were unhelpful. | Initial reads have finite deadlines and readable retry messages while preserving existing data. |
| Tour storage | Unavailable localStorage was treated as an unseen tour, contrary to its “stay quiet” fallback. | A browser without usable storage skips the tips. |
| Game touch | Another finger could steal/reset movement, look, or a held button; cancelled crouches could trigger an ollie. | Controls retain their owning pointer, ignore unrelated releases, and only deliberate crouch release pops. Pause/blur clear ownership. |

## Operational notes and remaining limits

- Game host, entry and changed UI import use revision `20261110bugs1`. Unchanged game imports/styles, map model/catalog, hike data and navigation keep their prior versions. Geometry, art assets, saved-game format and normal-map files were not changed.
- This release is live at https://byucalendar.com. Do not overwrite the ordinary calendar map when deploying the game UI.
- Browser checks used Chromium viewport resizing. Physical iOS/Android touch, native calendar sheets, Safari/Firefox, sustained game pacing, real inbox delivery and production concurrency were not exercised here. The touch regression suite executes the actual game UI handlers with distinct pointer IDs and cancellation events.
- Filter-dialog rendering mitigation: WebKit has reported [dialog-backdrop rendering issues](https://bugs.webkit.org/show_bug.cgi?id=303167), but this does not prove the reported empty-name symptom has that exact cause. The change removes the native-popup/blur combination only from the two affected forms; a physical-iOS check remains useful.
- Manual club/Handshake freshness, unconnected private/social sources, retention of removed events, and other previously documented coverage limitations remain. The source checks use retained seed records and deterministic fixtures; no fresh source audit or production reimport was performed.
- Preference writes from separate browser tabs/devices still use the existing last-write-wins API. The client queue prevents overlapping snapshots within one mounted calendar, and the server transaction keeps RSVP state consistent with whichever request wins.
